# Link.ly URL Shortener

Link.ly is a full-stack URL shortener built with Express, vanilla HTML, CSS, JavaScript, and Supabase. It creates six-character short codes, stores links in PostgreSQL through Supabase, and redirects visitors to the original URL.

## Features

- Shorten and validate HTTP/HTTPS URLs
- Six-character short-code generation
- Persistent link storage with Supabase
- `302 Found` redirects
- Copy and visit-link controls
- Recent links stored in the browser
- Light and dark themes
- Health-check endpoint

## Technology

- Node.js and Express
- Supabase JavaScript client and PostgreSQL
- HTML, CSS, and vanilla JavaScript
- Vitest and Supertest

## Architecture

```text
Browser
   |
   | POST /api/links
   v
Express application
   |
   | Supabase Data API
   v
PostgreSQL

Browser
   |
   | GET /:code
   v
Express application
   |
   | Look up destination
   v

```

## Local setup

### Requirements

- Node.js 20 or newer
- npm
- A Supabase project

### Installation

```bash
git clone https://github.com/grymoon5/url-shortener.git
cd url-shortener
npm install
```

Copy `.env.example` to `.env` and provide your own values:

```env
PORT=3000
BASE_URL=http://localhost:3000
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SECRET_KEY=your-server-side-secret-key
```

`SUPABASE_SECRET_KEY` must remain server-side. Never commit `.env` or expose this key in frontend JavaScript.

### Supabase database

Open the Supabase SQL Editor and create the links table:

```sql
create table if not exists public.links (
  id bigint generated by default as identity primary key,
  code varchar(6) not null unique,
  original_url text not null,
  created_at timestamptz not null default now()
);
```

The application uses a server-side Supabase secret key. Configure database access according to your Supabase security requirements and never place the secret key in browser code.

### Run locally

Development mode with automatic restart:

```bash
npm run dev
```

Production mode:

```bash
npm start
```

Open `http://localhost:3000` in a browser. Check the server with:

```bash
curl http://localhost:3000/health
```

Expected response:

```json
{"status":"ok","version":"post-route-test"}
```

## API

### Create a short link

```http
POST /api/links
Content-Type: application/json

{
  "url": "https://example.gov.sg/"
}
```

Successful response:

```json
{
  "code": "a1b2c3",
  "originalUrl": "https://example.gov.sg/",
  "shortUrl": "https://your-domain.example/a1b2c3"
}
```

### Redirect a short link

```http
GET /:code
```

Existing codes return a `302 Found` redirect. Unknown codes return `404 Not Found`.

## Deployment

The application can be deployed to any hosting provider that supports Node.js. The following example uses Render.

### Deploy with Render

1. Push the repository to GitHub without committing `.env`.
2. In Render, create a new **Web Service** and connect this GitHub repository.
3. Select the branch you want to deploy.
4. Configure the service:
   - Runtime: `Node`
   - Build command: `npm install`
   - Start command: `npm start`
5. Add these environment variables in the Render dashboard:
   - `SUPABASE_URL`
   - `SUPABASE_SECRET_KEY`
   - `BASE_URL`
6. Set `BASE_URL` to the public HTTPS address assigned by Render, without a trailing slash. For example:

   ```text
   https://your-service.onrender.com
   ```

7. Do not manually set `PORT` on Render; the platform supplies it automatically.
8. Deploy the service and visit `/health` on the public URL.
9. Create a link from the landing page, open its short URL, and confirm that it redirects correctly.

### Live Application

https://sniplinksg.onrender.com

## API Canary

The deployed application's health endpoint is monitored by an external HTTP canary:

`GET https://sniplinksg.onrender.com/health`

The canary periodically verifies that the API is publicly reachable and returns the expected operational status without writing data to the database.

### Production checklist

- Rotate any secret that was previously committed to Git.
- Confirm `.env` is ignored with `git check-ignore -v .env`.
- Set `BASE_URL` to the deployed HTTPS domain.
- Confirm the Supabase `links.code` column has a unique constraint.
- Run `npm test` before deploying.
- Verify `/health`, link creation, and redirects after deployment.

## Security

- `.env` is intentionally excluded from Git.
- `.env.example` should contain placeholders only.
- Supabase secret keys must only be used by the Express server.
- If a secret is exposed, rotate it immediately rather than bypassing GitHub push protection.
